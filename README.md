# Lumera — متجر مستحضرات تجميل إلكتروني متكامل

منصة تجارة إلكترونية متعددة البائعين (Multi-vendor Marketplace) لبيع مستحضرات التجميل،
مبنية بالكامل بواجهة عربية (RTL)، بثلاث لوحات: العملاء، الموردون، الإدارة.

---

## 1. التقنيات المستخدمة (كلها مجانية 100%)

| الغرض | التقنية | ملاحظة |
|---|---|---|
| الإطار (Frontend + Backend) | Next.js 14 (App Router) + TypeScript | مجاني ومفتوح المصدر |
| قاعدة البيانات | SQLite عبر Drizzle ORM + better-sqlite3 | ملف واحد محلي، لا يحتاج خادم منفصل |
| التصميم | Tailwind CSS، خط Cairo العربي (محمّل محليًا) | RTL كامل |
| المصادقة | bcrypt + JWT عبر كوكيز httpOnly | آمن، بدون خدمات خارجية |

> **ملاحظة هامة حول قاعدة البيانات:** كانت الخطة الأولى استخدام Prisma، لكن تم
> استبدالها بـ **Drizzle ORM + better-sqlite3** لأن Prisma يحتاج تحميل ملفات ثنائية
> (engines) من الإنترنت وقد تفشل هذه الخطوة خلف بعض الشبكات/الجدران النارية.
> Drizzle يعمل بنفس الكفاءة تمامًا بدون هذه المشكلة، وقاعدة البيانات حقيقية بالكامل
> (ملف `data/lumera.db`) وليست وهمية.

لا يوجد أي اعتماد على مفاتيح API أو خدمات مدفوعة في المشروع بأكمله.

## 2. التشغيل على Windows — خطوة بخطوة

### المتطلبات الأساسية (مرة واحدة فقط)
1. ثبّتي **Node.js** (الإصدار 20 أو أحدث) من الموقع الرسمي: https://nodejs.org
   (اختاري نسخة **LTS**). تأكدي من التثبيت بتشغيل موجه الأوامر (Command Prompt)
   وكتابة:
   ```
   node -v
   npm -v
   ```
   يجب أن يظهر رقم إصدار لكل أمر.

### خطوات تشغيل المشروع
1. افتحي **Command Prompt** أو **PowerShell** داخل مجلد المشروع (يمكنك كتابة
   `cmd` في شريط عنوان مستكشف الملفات وهو مفتوح على مجلد المشروع، ثم Enter).

2. ثبّتي الحزم البرمجية:
   ```
   npm install
   ```

3. (اختياري لكن موصى به) انسخي ملف الإعداد البيئي:
   ```
   copy .env.example .env.local
   ```
   يمكنك فتح `.env.local` بأي محرر نصوص وتغيير `JWT_SECRET` إلى نص عشوائي طويل
   (خصوصًا إذا كنتِ ستنشرين الموقع فعليًا لاحقًا).

4. أنشئي جداول قاعدة البيانات وزرعي بيانات تجريبية (خطوة واحدة تجهّز كل شيء):
   ```
   npm run setup
   ```
   هذا الأمر يقوم تلقائيًا بـ: تثبيت الحزم + إنشاء الجداول + تطبيقها + زراعة بيانات تجريبية.
   (إذا كنتِ نفذتِ `npm install` بالفعل في الخطوة 2، يمكنك بدلًا من ذلك تشغيل
   الأوامر الثلاثة التالية فقط):
   ```
   npm run db:generate
   npm run db:migrate
   npm run db:seed
   ```

5. شغّلي المشروع في وضع التطوير:
   ```
   npm run dev
   ```
   ثم افتحي المتصفح على: **http://localhost:3000**

### للنشر الفعلي (Production) على جهازك أو خادم
```
npm run build
npm run start
```

## 5. آلية العمولة والتسعير (كما طُلب بالضبط)

1. المورد يُدخل **سعره الخاص** عند إضافة/تعديل منتج.
2. الإدارة تحدد **نسبة عمولة** (عامة أو خاصة بكل تصنيف) من لوحة `الإدارة > العمولات`.
3. **سعر البيع للعميل = سعر المورد × (1 + نسبة العمولة٪)** — يُحسب تلقائيًا.
4. عند إنشاء طلب، يتم **تجميد** سعر المورد ونسبة العمولة وسعر البيع داخل الطلب نفسه
   (`order_items`)، بحيث لا تتأثر الطلبات القديمة أبدًا بأي تغيير لاحق في الأسعار
   أو العمولات — وهذا مُختبر وشغّال فعليًا.

---

## 6. الدفع (تحويل بنكي فقط، كما طُلب)

- بعد إنشاء الطلب، تظهر للعميل بيانات التحويل البنكي (اسم المصرف، صاحب الحساب،
  رقم الحساب/IBAN) والمبلغ والرقم المرجعي — هذه البيانات قابلة للتعديل من قاعدة
  البيانات مباشرة عبر جدول `site_settings`، أو يمكن إضافة صفحة إدارة لها لاحقًا
  إذا رغبتِ بذلك.
- يرفع العميل صورة إثبات الدفع من صفحة الطلب.
- تظهر الصورة للإدارة في `لوحة الإدارة > الطلبات > تفاصيل الطلب` لتقبلها أو ترفضها.
- **لا يُعتبر الطلب مدفوعًا فعليًا (`payment_confirmed`) إلا بعد موافقة الإدارة صراحة.**

---

## 7. ما تم اختباره فعليًا وهو شغّال بالكامل

- تسجيل حساب عميل/مورد ودخول وخروج (مصادقة حقيقية بكلمات مرور مشفّرة).
- تصفح، بحث، فلترة، وترتيب المنتجات من قاعدة بيانات حقيقية.
- إضافة/تعديل/حذف عناصر السلة.
- إتمام طلب → إنشاء عنوان شحن وسجل دفع ورقم مرجعي → خصم من المخزون تلقائيًا.
- رفع صورة إثبات دفع فعلية إلى القرص وربطها بالطلب.
- موافقة الإدارة على الدفع → تغيّر حالة الطلب تلقائيًا + إشعار للعميل.
- تغيير حالة الطلب عبر كل مراحل سير العمل (9 حالات) من لوحة الإدارة.
- إضافة مورد لمنتج → يظهر بحالة "قيد المراجعة" → موافقة الإدارة → يظهر للعملاء.
- تعديل نسبة العمولة من لوحة الإدارة → تحديث فوري لأسعار كل المنتجات المرتبطة.
- إدارة التصنيفات (إضافة/حذف).
- إحصائيات حقيقية لكل من المورد (مبيعاته وأرباحه) والإدارة (المبيعات والعمولات).
- بناء إنتاجي كامل (`npm run build`) ناجح 100% بدون أخطاء.

## 8. نقاط يمكن تطويرها لاحقًا (اختيارية، خارج نطاق الطلب الحالي)

- صفحة إدارة مخصصة لتعديل بيانات الحساب البنكي المعروضة للعملاء (حاليًا في جدول `site_settings`).
- بوابة دفع إلكتروني حقيقية (Stripe/PayPal) عند الرغبة بالتوسع مستقبلًا.
- نظام تقييمات ومراجعات فعلي من العملاء (حاليًا مجرد رقم تقييم تجريبي في البيانات).

## 9. النشر الفعلي على الإنترنت (Railway)

المشروع جاهز للنشر على [Railway](https://railway.app) مباشرة، مع تخزين دائم لقاعدة
البيانات وملفات الصور المرفوعة (لا تُفقد مع كل تحديث للموقع).

### الإعداد المطلوب على Railway

1. أنشئي مشروعًا جديدًا على Railway وربطيه بمستودع GitHub الخاص بهذا المشروع.
2. من إعدادات الخدمة (Service) → **Variables**، أضيفي:
   ```
   JWT_SECRET=<قيمة عشوائية طويلة وآمنة>
   DATA_DIR=/app/data
   DATABASE_PATH=/app/data/db/lumera.db
   ```
   لتوليد قيمة عشوائية آمنة لـ `JWT_SECRET`، شغّلي محليًا:
   ```
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
3. من تبويب **Volumes**، أضيفي قرص تخزين دائم واربطيه بمسار:
   ```
   /app/data
   ```
   هذا يضمن أن قاعدة البيانات وصور المنتجات وإثباتات الدفع تبقى محفوظة دائمًا،
   حتى بعد كل عملية نشر (Deploy) جديدة.
4. Railway سيكتشف المشروع تلقائيًا (Next.js عبر Nixpacks) وسيُشغّل `npm run build`
   ثم `npm run start` (سكربت `start` مُعدّ خصيصًا ليُجهّز التخزين الدائم ويُطبّق
   جداول قاعدة البيانات تلقائيًا قبل بدء الخادم).

### بعد أول نشر ناجح — مهم جدًا للأمان

البيانات التجريبية (`admin@lumera.test` بكلمة مرور معروفة للجميع) **غير آمنة على
الإطلاق للاستخدام الفعلي**. من طرفية Railway (Service → الأيقونة `>_` أو
"Shell")، شغّلي بالترتيب:

```
npm run db:create-admin
```
(يسألك عن اسمك وبريدك وكلمة مرور قوية، وينشئ حساب مدير حقيقي)

```
npm run db:reset-demo
```
(يحذف كل الحسابات والمنتجات والطلبات التجريبية نهائيًا — يطلب تأكيدًا صريحًا
قبل الحذف، ولا يمسّ التصنيفات أو إعدادات العمولة أو بيانات البنك)

بعدها سجّلي الدخول بحسابك الجديد فقط من `/login` على الرابط الحقيقي لموقعك.

### ربط الدومين الخاص بك

من تبويب **Settings → Networking** في خدمة Railway، أضيفي دومينك المخصص
(بعد شرائه من أي مزوّد مثل Namecheap أو Cloudflare)، ثم أضيفي سجل **CNAME**
الذي يعطيك إياه Railway إلى إعدادات الـ DNS الخاصة بالدومين. شهادة الأمان
(HTTPS) تُفعَّل تلقائيًا خلال دقائق قليلة بعد التحقق من الدومين.
